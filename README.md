# GUapp — V字モデル開発演習（Lv3）

Tech0 講義課題。GU の EC サイトを題材に、V字モデルの開発設計（要求仕様 → 要件定義 → 設計 → テスト設計 → 実装 → テスト → デプロイ）を一通り実施する。本プロジェクトは **Lv3**（GU アプリを見て自分で考える＝Lv2 要求仕様＋新機能）。

このファイルは他 PC で作業を引き継ぐためのメモ。

## 進め方（全ゲート共通）

各ゲートの成果物は 3 版方式で作成する。**完成品は with_ai 版**。

| 版 | 作り方 |
|---|---|
| no_ai | ユーザーが雑多に記載した内容を Claude が整理・文書化 |
| ai | no_ai を参照せず、前提条件とフォーマットのみ共有して Claude が単独設計 |
| with_ai | no_ai × ai を突き合わせ、双方の良い点を統合（出典タグで追跡） |

## 前提条件（変更不可）

- Web アプリとしてブラウザから利用
- フロントエンド：Next.js ／ バックエンド：FastAPI
- インフラ：Microsoft Azure（DB は Azure Database for MySQL Flexible Server）
- バックエンドを動かす Azure サービスは非機能要求を満たす前提で自分で選定
- Vercel・Streamlit は使用禁止（Week7 デプロイ時）

## 決定済みの方針

- **要求仕様書と要件定義書は分離**。数値基準・実現手段は要求仕様書に書かず、申し送り表（A-xx）で要件定義へ明示的に送る
- 全要求に ID を付与（REQ-FR／REQ-NFR／REQ-CO）。以降の工程は必ず ID を参照（欠番は再利用しない）
- 優先度は Must／Should／Could。Must 全充足が演習合格の最低ライン
- 画面の「状態・振る舞い」は要求として本文に記載、配置・寸法は付録（U-xx）からワイヤーフレームへ引き継ぐ
- 文書デザインは国内標準の要件定義書テンプレートを模倣（表ヘッダー薄グレー F2F2F2・細罫線格子・A4・メイリオ・本文 10.5pt）

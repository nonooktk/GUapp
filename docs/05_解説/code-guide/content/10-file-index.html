10. ファイル別の索引

レビュワーに「このファイルは何をしているか」を聞かれたときに、ここで場所を引いて画面に出す。対象は、FastAPI 側の apps/api/app/ 配下の Python 50 本（__init__.py を除く）と、Next.js 側の画面・Route Handler・部品・lib・proxy.ts の 76 本、合計 126 本である。git ls-files の結果から機械的に拾った。

事実: 対象コミットは origin/main の 2b9c87d。ファイル名の欄はファイル全体、「主な関数・型」の欄は各シンボルの定義に、それぞれ参照が付いている。テスト・設定ファイル・画像・CSS は索引に入れていない（機械抽出の対象外）。

層のバッジは、リクエストが通る順のどこに当たるかを示す。ブラウザに近いほうから、画面（画面・部品）、BFF（Route Handler とサーバー専用の lib/server）、FastAPI のルーター、サービス、リポジトリ、DB（モデル・接続・seed）と並ぶ。lib 直下の純粋関数は「Web 共通」とした。「主な関数・型」は各ファイルから 1〜4 個を選んだもので、全件ではない。

apps/web/lib/client/search-api.tsクライアントブラウザから検索系 BFF を呼ぶ薄いクライアント。GET だけなので CSRF は使わない。fetchSearchPage, fetchSuggestions, SearchApiError
apps/web/lib/client/use-session-item.tsクライアントsessionStorage の 1 キーを読むフック（useSyncExternalStore）。ハイドレーション前は null を返す。useSessionItem, useHydrated, parseJsonOrNull
apps/web/lib/cookie.ts共通Set-Cookie の文字列を組む純粋関数。cart_token は HttpOnly、csrf_token は JS が読むため HttpOnly なし。Secure は production だけ。buildSetCookie, buildCartTokenCookie, buildCsrfTokenCookie, readCookie
apps/web/lib/csrf-validation.ts共通CSRF（Double Submit Cookie）の判定規則。Cookie とヘッダの値が一致し、43 文字の base64url の形であること。isCsrfValid, isCsrfTokenShape
apps/web/lib/datetime.ts共通UTC の ISO 文字列を JST の表示形式にする。formatJst, formatJstDate
apps/web/lib/demo-banner.ts共通期間限定の帯に出す終了日（DEMO_PUBLIC_UNTIL）の解釈。形式が不正なら帯を出さずに警告ログを残す。parseDemoPublicUntil
apps/web/lib/demo-defaults.ts共通注文手続きフォームの初期値に入れる架空のダミー値と注意書き。本物の個人情報を入力させないための対策。DEMO_CHECKOUT_FORM, DEMO_NOTICE_TITLE, DEMO_NOTICE_BODY
apps/web/lib/env-validation.ts共通環境変数の検証ルール（純粋関数）。NEXT_PUBLIC_ に秘密の名前があれば拒否し、必須キーの欠落と TRUSTED_PROXY_HOPS の形を検査する。validateEnv, findLeakedPublicSecretKeys, WebEnv
apps/web/lib/format.ts共通金額表示。通貨記号は半角の ¥ に固定し、3 桁区切りだけ toLocaleString に任せる。formatYen, formatNumber
apps/web/lib/gender.ts共通性別区分（women・men・kids_teen）の表示名と URL パラメータ。GENDERS, isGenderSlug, genderLabel
apps/web/lib/image.ts共通商品画像 URL の組み立て（IMAGE_BASE_URL と image_path をつなぐ）。imageUrl
apps/web/lib/order-errors.ts共通注文系 API のエラー応答を、画面の戻し先（カート・注文手続き・その場に留まる等）に対応付ける表。routeOrderError, lookupErrorMessage, isOrderNumber, ORDER_MESSAGES
apps/web/lib/server/api.tsサーバー専用FastAPI を呼ぶ fetch ラッパー。X-Internal-Token を付け、エラー本文は許可したキーだけを通し、接続不可とタイムアウトは例外にする。apiFetch, sanitizeErrorBody, UpstreamUnavailableError
apps/web/lib/server/cart-proxy.tsサーバー専用カート系 BFF の共通の取り次ぎ。cart_token の Cookie を X-Cart-Token に載せ、応答のトークンで Cookie を更新する。proxyCartRequest, cartTokenHeaders, readJsonBody, validationError
apps/web/lib/server/catalog.tsサーバー専用Server Component から FastAPI を直接呼ぶデータ取得（カテゴリ・商品・公開設定・Cookie のカート）と、失敗を null に丸める loadOrNull。getCategories, getProducts, getCartFromCookie, loadOrNull
apps/web/lib/server/contents.tsサーバー専用コンテンツ系（お知らせ・FAQ・静的ページ）のデータ取得。getContents, getContent
apps/web/lib/server/csrf.tsサーバー専用CSRF トークンの乱数発行、リクエストの検証、未発行のときの Cookie 発行。generateCsrfToken, verifyCsrf, issueCsrfCookieIfMissing
apps/web/lib/server/env.tsサーバー専用process.env を検証して返すローダー。server-only を付けてあり、クライアントからの import はビルド失敗になる。getEnv
apps/web/lib/server/order-proxy.tsサーバー専用注文系 BFF の共通の取り次ぎ。X-Forwarded-For には信頼できる送信元 IP だけを載せ、429 の Retry-After を透過する。proxyOrderRequest, clientIp
apps/web/lib/server/search.tsサーバー専用検索のデータ取得（Server Component から FastAPI を直接呼ぶ）。getSearch, buildSearchQuery
apps/web/lib/types.ts共通FastAPI 応答の TypeScript 型。手で書いており、apps/api/openapi.json と突き合わせて保つ。Cart, OrderResponse, ProductDetail, ApiErrorBody
apps/web/proxy.tsBasic 認証サイト全体と BFF の /api/* を守る HTTP Basic 認証（Next.js 16 の proxy）。静的アセットは対象外にする。proxy, config

意見: 初めて見る人には、まず services/orders.py（注文確定）と repositories/orders.py（在庫引当の条件付き UPDATE）を開くと、このアプリの中心が短時間で伝わると思う。次に lib/server/api.ts（BFF から FastAPI への呼び出し）と core/security.py（内部トークン）を見せると、第 11 章の Q2 につながる。

4. カートの数量を変える・削除する

「カート画面で数量を変える」「カートから商品を削除する」「カート画面を表示する」「送料無料の案内（4,990 円以上で無料）はどこで決まるか」「合計金額はどう決まるか」

30 秒版

カート画面を最初に開くときは、Cookie に cart_token がある場合だけ、サーバー側のページが BFF を通らずに、FastAPI の GET /api/v1/cart を直接呼びます。数量の変更と削除は、ブラウザの CartView から BFF の PATCH と DELETE /api/cart/items/{id} を呼びます。BFF は CSRF を検証して、FastAPI に取り次ぎます。FastAPI は、自分のカートの明細かどうかと、数量の上限（1 明細 10 点、合計 50 点）を調べて更新し、明細・小計・送料・合計を作り直して、カート全体を返します。画面はその応答で全体を置き換え、ヘッダーのバッジも更新します。送料は、小計が閾値以上なら 0 円です。閾値と送料は system_settings の値です。

② 画面からバックエンドへ

この章の経路は 3 本です。画面を開くときは、Server Component が BFF を通さずに FastAPI を直接呼びます。数量変更と削除は、ブラウザから BFF を通ります。

経路呼ぶ側途中で通る場所FastAPI の呼び先
A. カート画面の初回表示サーバー側のページ（cart/page.tsx）lib/server/catalog.ts → apiFetch。BFF は通らないGET /api/v1/cart、GET /api/v1/settings/public
B. 数量変更ブラウザ（CartView）PATCH /api/cart/items/{id}（BFF）→ proxyCartRequestPATCH /api/v1/cart/items/{item_id}
C. 削除ブラウザ（CartView。確認ダイアログのあと）DELETE /api/cart/items/{id}（BFF）→ proxyCartRequestDELETE /api/v1/cart/items/{item_id}

  1. Cookie があれば、Server Component が最初のカートを取る。結果は 3 通り。Cookie が無い（null）なら空のカート、成功なら initialCart、失敗（非 2xx・接続不可）なら refetchOnMount（ブラウザで取り直す）。

    カート画面を最初に開くときは、サーバー側のページが、Cookie にあるトークンでカートを取って描画します。Cookie が無い人には、カートを作らずに空のカートを出します。

    次へ: getCartFromCookie にカーソルを置いて F12

  2. cookies() から cart_token を読み、X-Cart-Token に載せて FastAPI の GET /cart を直接呼ぶ。Cookie が無ければ呼ばない（描画中は Cookie を発行できないため）。BFF の Route Handler は通らない。

    ここも BFF は通りません。サーバーの中から、カートのトークンをヘッダーに載せて FastAPI を呼びます。

    次へ: URL の文字列なので F12 では飛べない。⌘P で apps/api/app/routers/cart.py を開き、⌘⇧O で get_cart へ

  3. GET /api/v1/cart。X-Cart-Token を受け、サービスを呼ぶ。これがカート画面のリクエスト先。

    リクエスト先は FastAPI の GET /api/v1/cart です。

    次へ: ⌘P で apps/web/app/cart/page.tsx に戻り、設定を取る行（getPublicSettings）へ

  4. 送料無料の閾値を GET /settings/public（DS-API-020）から取る。取れなければ予備値 FALLBACK_FREE_SHIPPING_THRESHOLD = 4990 を使う。

    カートの応答にも閾値は入っています。ただ、空のカートの表示に使うため、公開設定からも取っています。取れなかったときは、予備の 4,990 円を使います。

    次へ: getPublicSettings にカーソルを置いて F12

  5. apiFetch で /settings/public を直接呼ぶ。税率・送料・閾値の 3 つが返る。

    公開設定も、サーバーの中から直接呼びます。

    次へ: ⌘P で apps/api/app/routers/settings.py を開く

  6. GET /api/v1/settings/public。system_settings の 3 キー（tax_rate・shipping_fee・free_shipping_threshold）だけを返す。

    送料の閾値と送料は、DB の system_settings にある値で、この API が返します。

意見（コードを読んだ範囲の推測）: GET /api/v1/cart は、トークンが未知か注文済みのとき、カートを新しく作る（DB に書く）作りです。Server Component から呼ぶ初回表示でも同じです。ただ、ここでは Cookie を発行できないので、返ってきた新しいトークンは、次に BFF を通るまで保存されません。画面には空のカートが出るので利用者には見えませんが、空のカートの行が増えることはあります。実機では確かめていません。

  1. 数量セレクト（1〜10）。変更するとすぐ onQuantityChange が呼ばれる。同じ数量なら何もしない。処理中（busyItem）は、その明細のセレクトが disabled になる。

    数量を選び直すと、確認なしですぐに更新します。更新中は、その明細のセレクトを押せなくします。

    次へ: onQuantityChange にカーソルを置いて F12（同じファイルの中の定義へ飛ぶ）

  2. updateCartItem(item_id, quantity) を呼び、戻ってきたカートで apply（画面の state とバッジを更新）する。成功すると、トースト「数量を変更しました」が 2.5 秒出る。失敗は handleError へ。

    数量の変更は、明細の ID と新しい数量を渡して、updateCartItem を呼びます。

    次へ: updateCartItem にカーソルを置いて F12

  3. PATCH /api/cart/items/{itemId}、本文は {quantity}。mutate を通るので、CSRF のヘッダーが付く（3 章の順路 A と同じ）。

    送り先は、同じ Next.js の /api/cart/items/明細の ID です。

    次へ: URL の文字列なので F12 では飛べない。⌘P で apps/web/app/api/cart/items/[id]/route.ts を開き、⌘⇧O で PATCH へ

  4. 順に、① CSRF の検証（通らなければ 403） ② [id] が正の整数か（違えば 404 not_found） ③ quantity が正の整数か（違えば 400 validation_error） ④ proxyCartRequest で FastAPI の PATCH /cart/items/{id}。

    BFF は、CSRF、明細の ID の形、数量の形の順に確かめて、通ったものだけを FastAPI に渡します。

    次へ: proxyCartRequest にカーソルを置いて F12

  5. 3 章と同じ共通の取り次ぎ。cart_token Cookie を X-Cart-Token に載せ替え、apiFetch が X-Internal-Token を付ける。

    カートの追加と同じ関数を使います。Cookie のトークンをヘッダーに載せ替えて、FastAPI を呼びます。

    次へ: ⌘P で apps/api/app/routers/cart.py を開き、⌘⇧O で update_item へ

  6. @router.patch("/items/{item_id}")。item_id はパス、本文は CartItemPatchIn、トークンはヘッダー。これがリクエスト先のバックエンド。

    リクエスト先は FastAPI の PATCH /api/v1/cart/items/明細の ID で、routers/cart.py の update_item です。

  1. 「削除」ボタンは、すぐには消さず、pendingDelete に入れるだけ。すると ConfirmDialog（「商品を削除しますか？」）が開く。キャンセルにフォーカスが当たり、Escape で閉じる。

    削除ボタンを押しても、すぐには消えません。まず確認のダイアログを出します。

    次へ: 同じファイルの末尾にある ConfirmDialog の onConfirm={onConfirmDelete} で、onConfirmDelete にカーソルを置いて F12

  2. 「削除する」を押すと onConfirmDelete が動く。deleteCartItem を呼び、戻ってきたカートで置き換え、ダイアログを閉じて、トースト「{商品名} を削除しました」を出す。

    確認で「削除する」を押したら、deleteCartItem を呼びます。

    次へ: deleteCartItem にカーソルを置いて F12

  3. DELETE /api/cart/items/{itemId}。本文は無い。mutate を通るので、CSRF のヘッダーが付く。

    送り先は、数量変更と同じ URL で、メソッドだけが DELETE です。

    次へ: URL の文字列なので F12 では飛べない。⌘P で apps/web/app/api/cart/items/[id]/route.ts を開き、⌘⇧O で DELETE へ

  4. PATCH と同じく、CSRF の検証と [id] の形の確認のあと、proxyCartRequest で FastAPI の DELETE /cart/items/{id}。取り次ぎの中身は順路 B の stop 5 と同じ。

    削除も、CSRF と ID の形を検証してから、同じ取り次ぎの関数で FastAPI に渡します。

    次へ: ⌘P で apps/api/app/routers/cart.py を開き、⌘⇧O で remove_item へ

  5. @router.delete("/items/{item_id}")。これがリクエスト先のバックエンド。応答は、削除後のカート全体。

    リクエスト先は FastAPI の DELETE /api/v1/cart/items/明細の ID で、routers/cart.py の remove_item です。

③ バックエンドの処理

  1. /api/v1 配下のルーターすべてに verify_internal_token が付く。cart.router もここで登録される。

    /api/v1 の下は、この 1 か所で、内部トークンの検証が必須になっています。

    次へ: verify_internal_token にカーソルを置いて F12

  2. X-Internal-Token が無い・一致しないと 401 unauthorized。

    BFF 以外からの呼び出しは、ここで 401 になります。

    次へ: ⌘P で apps/api/app/routers/cart.py を開き、⌘⇧O で update_item へ

  3. パスの item_id を整数として検証し、本文を CartItemPatchIn で受ける。形が合わないと 400 validation_error。

    ルーターは、明細の ID と本文の形を確かめて、サービスに渡すだけです。

    次へ: CartItemPatchIn にカーソルを置いて F12（本文の型は schemas/cart.py）

  4. quantity は 0 より大きい整数。上限（10・50）はここには書かない。

    数量は、0 より大きい整数であることだけを、ここで確かめます。

    次へ: ⌘P で apps/api/app/services/cart.py を開き、⌘⇧O で update_item へ

  5. 順に、① resolve_cart で自分のカートを特定 ② get_item で自分のカートの明細だけを探す（他人のもの・存在しないものは rollback して 404 not_found） ③ check_limits で上限を検査（超えたら rollback して 422） ④ set_item_quantity と commit ⑤ build_cart_response。在庫の検査はしない。

    サービスは、まず自分のカートの明細かどうか、次に上限を超えないかを調べて、数量を更新します。在庫はここでは見ません。

    次へ: get_item にカーソルを置いて F12

  6. 条件に cart_id も入れるので、他人の item_id を送っても見つからない（IDOR の対策。設計仕様書 7.5）。見つからなければ None。

    明細の ID に加えて、自分のカートであることも条件にしています。他人のカートの明細は見つからないので、触れません。

    次へ: ⌘P で services/cart.py に戻り、others の行へ

  7. 上限の検査は、「他の明細の合計 + 新しい数量」で行う。

    合計 50 点の上限は、この明細を直したあとの合計で判定します。

    次へ: check_limits にカーソルを置いて F12

  8. 1 明細が 10 点を超えると 422（limit は 10）、合計が 50 点を超えると 422（limit は 50）。数量のセレクトは 1〜10 なので、画面から操作して引っかかるのは合計 50 点の上限だけ。

    上限を超えるときは 422 を返して、更新はしません。

    次へ: ⌘P で apps/api/app/repositories/carts.py を開き、⌘⇧O で set_item_quantity へ

  9. UPDATE cart_items SET quantity = … WHERE id = …。

    数量を更新する SQL です。

    次へ: ⌘P で apps/api/app/models/cart.py を開き、⌘⇧O で CartItem へ

  10. cart_items.quantity（quantity > 0 の CHECK）。(cart_id, variant_id) は UNIQUE。

    数量は cart_items テーブルの quantity 列で、0 以下は DB の制約でも入りません。

  1. get_item が None なら rollback して 404 not_found。あれば削除して commit し、build_cart_response。最後の 1 件を消すと items が空になり、金額は 0。

    削除も、自分のカートの明細だと確認してから、行を消します。

    次へ: delete_item にカーソルを置いて F12

  2. DELETE FROM cart_items WHERE id = …。

    行を消す SQL です。カートそのものは残ります。

    次へ: ⌘P で services/cart.py を開き、⌘⇧O で build_cart_response へ

  3. 明細は fetch_lines で 1 クエリ。line_total = unit_price * quantity。金額は calc_totals。空のカートは金額 0（empty_cart の 409 は出さない）。item_count は数量の合計。

    数量変更でも削除でも、最後にカート全体を作り直して返します。金額の計算はここで行い、画面側ではしません。

    次へ: calc_totals にカーソルを置いて F12

  4. 小計 → 送料 → 合計（小計 + 送料）→ 内税の順。明細が 0 件のときは 409 empty_cart（build_cart_response は先に除いている）。金額はすべて int。

    小計から送料を決めて、合計を出します。

    次へ: calc_shipping_fee にカーソルを置いて F12

  5. 小計が閾値以上なら 0、未満なら設定の送料。4,989 → 550、4,990 → 0。判定は小計（送料・値引き前）に対して行う。

    送料が無料になるのは、小計が閾値以上のときです。閾値の 4,990 円ちょうども、無料です。

    次へ: ⌘P で apps/api/app/services/settings.py を開き、⌘⇧O で get_public_settings へ

  6. 税率・送料・閾値は system_settings（DS-TBL-21）の値。キーの欠落や型の不正は 500 internal_error（設定の投入漏れとして扱う）。

    閾値と送料は、DB の設定の値で、コードには書いていません。だから、変えても再デプロイは要りません。

    次へ: ⌘P で apps/api/app/services/cart_rules.py を開き、⌘⇧O で stock_status へ

  7. 明細の在庫状態。非公開か在庫 0 なら out_of_stock、在庫が数量より少なければ insufficient、それ以外は ok。1 件でも ok でなければ、can_checkout は false。

    在庫の状態は、カートを返すたびに、そのときの在庫から計算します。数量を変えても在庫では止めず、状態として知らせる作りです。

数量変更と削除で起きうる失敗と、返るステータス・code の一覧です。

④ 応答から表示まで

  1. 応答は、明細（items）・item_count・subtotal・shipping_fee・total・free_shipping_threshold・can_checkout。明細の 1 件は CartLineOut（stock_status・line_total を含む）。

    画面で使う値は、すべてこの応答に入っています。画面側で、金額や在庫の判定を計算し直すことはありません。

    次へ: ⌘P で apps/web/lib/server/cart-proxy.ts を開き、⌘⇧O で proxyCartRequest へ

  2. 成功は、FastAPI のカート全体を、そのまま 200 で返す（Cache-Control: no-store）。

    BFF は、成功なら FastAPI の応答を、そのまま返します。

    次へ: ⌘P で apps/web/components/CartView.tsx を開く

  3. apply が、setCart（画面全体）と applyCart（ヘッダーのバッジ。3 章の順路 A と同じ経路）の 2 つを呼ぶ。明細・小計・送料・合計・can_checkout は、応答のカートから描き直される。

    返ってきたカートで、画面全体を置き換えます。同じ応答で、ヘッダーのバッジも更新します。

    次へ: 同じ関数の下の、明細を描く items.map へ

  4. 明細ごとに、商品名・色/サイズ・単価・数量・小計。stockWarning(item.stock_status) が null でなければ、行の下に赤字の警告（role="alert"）。

    明細は、応答の items から描きます。在庫に問題がある行には、警告を出します。

    次へ: 同じ関数の下の、金額欄（送料の行）へ

  5. 送料の行。閾値は応答の free_shipping_threshold（無ければ props）で、「（4,990 円以上で無料）」と添える。shipping_fee が 0 のときは「無料」、それ以外は金額。「あと何円で無料」の計算はしていない。

    送料の案内は、閾値の金額を添えるところまでです。送料が 0 円のときは、「無料」と出します。

    次へ: 同じ関数の下の、canCheckout の分岐へ

  6. can_checkout が false なら、「⚠ 在庫切れ・在庫不足の商品があるためレジへ進めません」を出し、「レジへ進む」は disabled のボタンになる。true なら /checkout へのリンクになる。

    在庫に問題のある明細が 1 つでもあれば、レジへ進むボタンは無効になります。

    次へ: stockWarning の文言は ⌘P で apps/web/lib/cart-messages.ts を開き、⌘⇧O で stockWarning へ

  7. 在庫状態の警告文。ok は null、insufficient は「在庫が不足しています」、out_of_stock は「在庫切れのため購入できません」。

    警告の文言は、在庫状態の値ごとに決めてあります。

  1. 数量変更・削除の失敗は、CartApiError から status と body を取り出し、cartErrorMessage の文言をエラーのトーストに出す。数量変更が失敗しても state は更新しないので、セレクトは元の数量に戻る。削除が失敗したときは、ダイアログを閉じてからトーストを出す。

    失敗したときは、エラーの種類に合わせた文言をトーストで出します。画面のカートは更新しないので、元の数量のままです。

    次へ: cartErrorMessage にカーソルを置いて F12

  2. code ごとの固定文言（3 章の表と同じ）。他人の明細や、すでに削除された明細への操作は 404 not_found で、「商品が見つかりませんでした」。

    すでに消えている明細を操作したときは、「商品が見つかりませんでした」と出ます。

    次へ: ⌘P で apps/web/components/CartView.tsx を開き、読み込み失敗の表示を見る

  3. 初回表示の取得に失敗し（refetchOnMount）、ブラウザからの取り直し（fetchCart）も失敗したときの表示。role="alert"。

    サーバー側の取得に失敗したときは、ブラウザからもう一度取りに行きます。それも失敗したら、この文言を出します。

    次へ: 同じ関数の下の、空のカートの表示へ

  4. 明細が 0 件のとき（Cookie 無し・最後の 1 件を削除したあとを含む）の表示。「買い物を続ける」でホームへ。

    明細が 1 つも無いときは、空のカートの表示と、買い物を続けるボタンを出します。

失敗・特別な状態のときの画面の出し分けです。

場面画面の表示出す場所

削除に成功トースト「{商品名} を削除しました」。明細が消え、金額・バッジが更新される

詰まりそうな質問

1〜2分他の人のカートの商品を、消したり変えたりできませんか

できません。リポジトリの get_item が、明細の ID に加えて自分のカートの ID も条件にして探すので、他人の item_id を送っても見つからず、404 not_found になります。他人のものと存在しないものは区別しません。BFF は [id] を正の整数に限っています。確認は IT-012-01 ですが、結合テストは CI でスキップされます。この点は先に伝えておいたほうがよいです。

追撃: カートの持ち主はどう見分けていますか

Cookie の cart_token（43 文字の乱数）です。BFF が X-Cart-Token ヘッダーに載せ替えて FastAPI に渡し、FastAPI がトークンからカートを特定します。3 章の順路 B に発行の流れがあります。

1〜2分送料無料の閾値は、どこで決まっていますか。画面と API で食い違いませんか

system_settings の free_shipping_threshold で決まり、金額の判定は API の calc_shipping_fee が行います。画面は、API の応答の閾値と送料をそのまま表示するだけで、計算はしません。cart/page.tsx の予備値 4,990 円は、公開設定の取得に失敗したときの表示だけに使います（既知の弱点 C5）。

1〜2分数量を変えるとき、在庫は確認していますか

確認していません。設計仕様書 DS-PRC-011 で、数量が在庫を超えていても受け付け、在庫の確定は注文時の引当で行うと決めているためです。そのかわり、カートを返すたびに明細ごとの stock_status を計算し、在庫が足りない明細があれば警告を出して、「レジへ進む」を無効にします（ST-F009-05 は手動で確認）。

## 3. ローカル MySQL の用意（決定事項・案 A）

Docker と管理者権限が無いため、MySQL 8.4 の zip（noinstall）版をユーザー領域 `%LOCALAPPDATA%\guapp-mysql\` に展開し、`scripts/mysql-local/` の PowerShell で初期化・起動・停止する。DB は `guapp`（開発）と `guapp_test`（IT 用）の 2 つ。文字コード utf8mb4、タイムゾーン UTC（設計書 DS-DEC-25 と同じ設定値）。Docker がある PC では `docker compose up -d` で同じ設定の MySQL が立つよう `docker-compose.yml` も置く。CI は GitHub Actions の `services: mysql:8.4`。

## 5. 実装上の取り決め（設計書からの追加分のみ）

- **層**: ルーター（入出力のみ）→ サービス（業務規則・409/422 の判定）→ リポジトリ（SQL）。UT はサービス層の関数に対して書く。ルーターに `HTTPException` を書かない
- **金額**: `int` のみ。`Decimal` は tax_rate の変換時だけ。関数入口で `isinstance(int)` を検査
- **在庫引当**: `UPDATE variants SET stock = stock - :q WHERE id = :id AND stock >= :q` を 1 文で。SQLAlchemy Core で書き、生 SQL 文字列連結は禁止
- **同時性フック**: `APP_ENV=test` のときだけ有効な「処理中カウンタ」と「引当の読み書き間の待ち」を `app/core/testing_hooks.py` に置く。本番ビルドでは import されないことを UT で確認
- **UT の DB**: UT-014-03/04 は SQLite インメモリ（aiosqlite）。IT は MySQL のみで、setup でエンジン名を assert
- **テスト命名**: `test_<ID小文字>_<要点>`（例 `test_ut_021_02_shipping_threshold`）。ID で設計書と往復できるようにする
- **web の秘密**: `lib/server/` 配下は `import "server-only"`。`NEXT_PUBLIC_` に秘密名を含む変数があればローダーが起動時に例外

## 7. リスクと対処

| リスク | 影響 | 対処 |
| --- | --- | --- |
| MySQL zip 版が Windows で起動しない（VC++ ランタイム等） | Wave 0 が止まる | Wave 0 の最初に単独で確認。失敗時は MySQL 8.0 zip か、のんちゃんが管理者で Docker Desktop を入れる |
| asyncmy の Windows 3.13 wheel が無くビルドが走る | 環境構築が長引く | aiomysql（pure Python）に切り替え。接続 URL の scheme 変更のみ |
| Next.js 16 の Route Handlers での Cookie・CSRF 実装に癖がある | Wave 2 の BFF が遅れる | Wave 0 で `/api/cart` の Cookie 発行だけ先に通し、方式を固定する |
| 同時実行テストが CI 上で不安定（フレーク） | CI が赤になり続ける | 1.4 の反復 30 回は IT 側に限定。CI のタイムアウトを明示。フレークは記録して原因を潰す（リトライで隠さない） |
| public リポジトリへの秘密 push | 信用失墜 | gitleaks pre-commit。`.env` は最初のコミットで gitignore |

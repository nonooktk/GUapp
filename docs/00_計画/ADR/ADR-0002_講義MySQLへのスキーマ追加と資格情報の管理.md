# ADR-0002 講義 MySQL へのスキーマ追加と資格情報の管理

| 項目 | 内容 |
| --- | --- |
| 状態 | 承認 |
| 日付 | 2026-09-24 |
| 決定者 | 統括（Oya） |

## 背景

講義の指示は「Step3-1,2 で使った MySQL にスキーマを新規追加して使用する」というものである。講義の MySQL は Azure Database for MySQL Flexible Server `gen12-mysql-pos`（リソースグループ `rg-001-gen12`）であり、受講生で共用と推定される（推定であり、確認情報ではない）。管理者の資格情報は統括が保有している。

## 決定

- スキーマ名は `guapp_nonooktk` とする。共用サーバーで他の受講生と衝突しないよう GitHub ユーザー名を付ける。結合テスト用のスキーマは `guapp_nonooktk_test` とする。DB 名が `_test` で終わっていないと IT が即中止する安全装置（`引継ぎメモ_20260924.md` 6 章、conftest の実装）に合わせるためである
- アプリ用の専用ユーザーを新規に作り、この 2 スキーマだけに権限を与える（最小権限）。管理者の資格情報はアプリにも `.env` にも入れない
- 資格情報の置き場は次のとおりとする
  - 統括が自分の手で `apps/api/.env`（`.gitignore` 対象、pre-commit の「forbid .env files」と CI の gitleaks で二重に防御）に書く
  - チャットやエージェントへの指示文には貼らない（会話ログに残るため）
  - 管理者パスワードはパスワードマネージャーに保管する
- 接続は SSL 必須とする。サーバーのファイアウォールは開発 PC の IP のみ許可し、不要になったら削除する
- 切り替え後もローカル MySQL（Docker／zip）は開発用に残し、`.env` の `DATABASE_URL` で切り替える

## 判断基準と理由

- 共用サーバーでの名前衝突を避けるため、スキーマ名に受講生固有の識別子（GitHub ユーザー名）を付ける
- 結合テストが開発データを壊さないための既存の安全装置（`_test` サフィックス）に、新しいスキーマ名も合わせる
- 管理者資格情報の漏えい範囲を「自分の 2 スキーマだけ」に限定するため、アプリ用の専用ユーザーを別途作り最小権限にする
- 資格情報を会話ログに残さないため、統括自身が `.env` に直接書く運用とする
- 開発中の事故を避けるため、ファイアウォールは開発 PC の IP のみに絞り、SSL を必須にする

## 検討した代替案

| 案 | 内容 | 不採用の理由 |
| --- | --- | --- |
| 案 A | 管理者ユーザーでそのまま接続する | 手順は簡単だが、漏えい時に他の受講生のスキーマまで触れる権限を持ってしまうため不採用 |
| 案 B | ローカル MySQL のみで進める | 講義の指示（Step3-1,2 の MySQL にスキーマを新規追加して使用）に反するため不採用 |

## 影響とリスク

- 共用サーバーのため、他の受講生の負荷や障害の影響を受ける可能性がある
- ファイアウォールの IP 許可は、開発 PC（自宅など）の IP が変わるたびに再設定が必要になる

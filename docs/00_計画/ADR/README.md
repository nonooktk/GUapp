# ADR（Architecture Decision Record）一覧

## 目的

ADR は「なぜそう決めたか」を後から辿るための記録である。判断の時点で見えていた前提・比較した代替案・選ばなかった理由を残し、状況が変わったときに「決め直すべきか」を判断できるようにする。

## DS-DEC との役割分担

- **DS-DEC**（設計仕様書の中の設計判断）＝ API・DB・セキュリティ・インフラ構成など、設計レベルの判断。正本は `docs/03_設計仕様書/GU_ECsite_設計仕様書_P1_draft-v3.md` の 9.1 章。
- **ADR**＝ 工程の分け方・実装範囲・環境構築・調達（外部サービスの資格情報の扱い等）など、計画レベルの判断。

DS-DEC の内容はこの一覧には複製しない。9.1 章を直接参照する。

## 書式

- 番号は `ADR-NNNN`（4 桁連番、欠番は再利用しない）
- 状態は次のいずれか
  - 提案 … まだ承認されていない
  - 承認 … 現在有効
  - 置換済み → ADR-NNNN … 後継の ADR に置き換えられた（後継番号を明記）
- 各 ADR は次の章立てで書く
  1. 背景
  2. 決定
  3. 判断基準と理由
  4. 検討した代替案
  5. 影響とリスク
  6. 関連

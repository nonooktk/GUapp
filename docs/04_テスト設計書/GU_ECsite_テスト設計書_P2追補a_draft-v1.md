## 0. 本書の位置づけ

本書は本編（`GU_ECsite_テスト設計書_P1_draft-v2.md`、以下「本編」）の追補であり、本編の 0 章で定義した 4 レベル対応（AT／ST／IT／UT）とトレーサビリティの枠組みをそのまま使い、**P2-a で追加した設計 ID に対応するテストだけ**を新設する。本編で定義済みの ID 体系（`AT-nn`／`ST-F<機能番号>-nn`／`IT-<DS 番号>-nn`／`UT-nnn-nn`）、正常・異常・境界の 3 区分、実施環境の方針を継承する。

Azure MySQL 接続（ADR-0002）に関するテストのみ、ID を `IT-AZ-nn` とする（対象が特定の DS-API／DS-PRC に紐づかないインフラ確認のため、本編の命名規則の例外として新設する）。

## 1. テスト方針（差分）

本編 1 章の方針（レベル別方針・合否基準・環境）をそのまま使う。差分は次の 2 点のみ。

1. **Azure MySQL 接続のテスト（IT-AZ-01・02）は Azure 環境が無いと実施できない**。P1 のようにローカル Docker MySQL では代替できないため、実施時期を「P2 Wave 0（接続の素振り）」に固定し、それまでは「未実施」として扱う（本編 1.2「不合格は設計仕様書の該当 DS-ID とセットで記録」と同様、未実施も理由とセットで記録する）。**2026-09-24 訂正**: この 2 件は pytest の自動結合テスト（213 件）には含めず、講義サーバーへの**手動接続確認**として実施する（設計仕様書追補 DS-DEC-44・8.4）。
2. 検索・コンテンツ系は認証やトランザクション排他制御を持たない読み取り専用 API のため、本編 1.4「同時実行テストの実施条件」は適用しない（対象が無い）。

## 8. 申し送り

- ST-SEC-13（コンテンツ XSS）は P2-a 時点で管理画面が無いため DB 直接更新で代替する。F-034（管理：コンテンツ、P3）の管理画面ができた時点で、画面経由の入力でも同じ試験をやり直すこと
- 検索 API のレート制限は ADR-0003（`docs/00_計画/ADR/ADR-0003_検索APIのレート制限の見送り.md`）により P2-a では見送りが確定した。P2-d 着手前に ADR-0003 を再訪し、必要になった場合は ST・IT を追加すること
- Azure 側の `max_connections` 上限確認（設計仕様書追補 9.2 要検証 #4）は `DB_POOL_SIZE`／`DB_MAX_OVERFLOW`（DS-DEC-46・UT-DBCONF-01）で対応済み。結果次第で講義サーバー接続時の推奨値（既定 5／5）を調整するだけで済む
- **2026-09-24 追加**: DB 照合順序（`utf8mb4_0900_ai_ci`）の寛容性（全角半角・ひらがなカタカナ・清濁音の同一視）は P2-a のテスト（ST-F003-03・07、IT-004-08）で確認する。将来、DB の照合順序やドライバのバージョンが変わった場合は、この挙動が変わりうるため再確認すること

## 0. 本書の位置づけ

本書は V 字モデルの右側にあたる。左側の各文書に対応するテストレベルを 1 冊にまとめ、10 章のトレーサビリティ表で REQ → F → DS → テスト ID をつなぐ。テストは設計と同じタイミングで設計し、実装後に実施する。

| 左側（入力） | 右側（テスト） | ID 体系 | 粒度 | 実施環境 |
| --- | --- | --- | --- | --- |
| 要求仕様書 REQ-xx・ユーザーストーリー US-xx | 受け入れテスト | AT-xx | 業務フロー・ユーザーストーリー単位。ブラウザ操作で確認 | ローカル（P1）→ Azure（P2） |
| 要件定義書 F-xxx・6 章非機能 | システムテスト | ST-Fxxx-nn | 機能単位と非機能。画面からの確認と HTTP での確認 | ローカル（P1） |
| 設計仕様書 基本設計 DS-API・DS-TBL・DS-SCR | 結合テスト | IT-nnn-nn | BFF・FastAPI・DB の経路。外部 IF はスタブ | Docker MySQL＋FastAPI（pytest） |
| 設計仕様書 詳細設計 DS-PRC・関数 | 単体テスト | UT-nnn-nn | 関数・コンポーネント単位 | pytest／Vitest |

テスト項目は 3 区分で書く。**正常**＝仕様どおりの入力で期待結果になる。**異常**＝仕様外の入力・状態で設計した戻し方になる。**境界**＝上限・下限・閾値の前後で挙動が切り替わる。

完了条件は実装フェーズ計画 2 章の P1 出口条件に合わせる。AT-01（ゲスト購入）に合格し、IT・UT が全件緑、375px で導線が通ること。要件定義書 7 章の「Must 18 件すべてに受け入れ基準 1 件以上」は P1 対象の Must 8 件で満たし、残りは P2 追補で満たす。

## 1. テスト方針

### 1.1 レベル別の方針

| レベル | 目的 | 実施方法 | 自動化 | 実施時期 |
| --- | --- | --- | --- | --- |
| AT | 利用者の目的が達成できるか | 手順書に沿ってブラウザで操作。PC 幅と 375px の 2 回 | 手動（Playwright 化は P2 で判断） | P1 実装完了後 |
| ST | 機能要件・非機能要件を満たすか | 画面操作と HTTP クライアント（curl）。セキュリティ項目は開発者ツールで確認 | 一部を pytest で自動化 | P1 実装完了後 |
| IT | API と DB の経路が設計どおり動くか。同時実行・異常系 | pytest＋httpx で FastAPI を起動し Docker MySQL に接続。並行実行は asyncio.gather | 全件自動 | P1 実装と並走 |
| UT | 関数・コンポーネントが仕様どおりか | pytest（api）、Vitest＋Testing Library（web） | 全件自動。CI で実行 | 実装と同時 |

### 1.2 合否基準

- 期待結果と一致すれば合格。期待結果に幅がある項目（応答時間など）は P2 の Azure 環境で計測するため P1 では対象外
- 不合格は設計仕様書の該当 DS-ID とセットで記録し、設計の誤りか実装の誤りかを切り分ける
- IT・UT は CI で実行し、1 件でも失敗すれば main へのマージを止める

### 1.3 テスト環境とデータ

| 項目 | 内容 |
| --- | --- |
| DB | Docker MySQL 8.4。テスト開始時に `alembic upgrade head` → `seed.py` で初期化 |
| seed | 商品 30 点（色 2・サイズ 3）。テスト用に次を追加する：在庫 0 のバリエーション（V-STOCK0）、在庫 1 のバリエーション（V-STOCK1）、非公開商品（P-UNPUB）、全バリエーション在庫 0 の商品（P-ALL0） |
| system_settings | tax_rate=0.10、shipping_fee=550、free_shipping_threshold=4990、payment_timeout_minutes=30 |
| 決済 | `PAYMENT_STUB_RESULT=ok`（既定）。決済 NG のテストは `ng` に切り替えて実行 |
| メール | ログ出力スタブ。送信内容はログで確認 |
| 個人情報 | 配送先・メールはダミーのみ（例：テスト 太郎、test@example.com） |
| ブラウザ | Chrome 最新。375px は開発者ツールのデバイスモード |
